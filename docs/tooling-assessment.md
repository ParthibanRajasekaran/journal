# Tooling assessment: free, open source, security first

Status: Draft · Date: 2026-10-29 · Related: all ADRs

## How to read this

- **Selection rule:** the tool must be free and open source, actively maintained, and must not weaken security. Where a free tool is weaker, we say so and add a compensating control.
- **Licence column** is from general knowledge of each project. **Verify before adoption** by reading the project's LICENSE file and the dependency tree. Nothing here has been checked against a live package yet.
- **Version pins** are not included. Pin exact versions when a tool is first added.

## 1. Summary of recommendations

| Area | Pick | Runner-up | Why |

## 2. Detail by area

### 2.1 API and contract

- **OpenAPI 3.1** is generated by FastAPI. Keep `docs/openapi.yaml` as the reviewed contract and diff it against the generated one in CI, so drift between code and contract fails the build.
- **Redocly CLI** (MIT, verify) lints the contract and checks breaking changes between versions. Spectral (Apache-2.0, verify) is the alternative.
- Security: Redocly can flag operations with no security requirement; use this to enforce "every non-public route is authenticated."

### 2.2 Policy and guardrails

- **OPA** (Apache-2.0, verify) is the policy engine. Rego is a declarative language with a built-in test runner. Policies live in `policy/`, are versioned in git, and are reviewed like code.
- **Cedar** (Apache-2.0, verify) is simpler for pure authorization and has a formal analysis story, but it does not cover the output-validation and agent-change rules we also need. OPA covers all of them with one tool.
- **Casbin** is fine for role checks but weaker for the richer rules here.
- Trade-off: OPA adds a process or a library and a new language. The benefit is one policy model for authorization, consent, output checks, and agent change rules.

### 2.3 Authentication

- Google is the identity provider, so we do not store passwords. The API verifies Google ID tokens with a maintained library and checks issuer, audience, expiry, and nonce.
- **PyJWT** (MIT, verify) for our own access tokens. Always pass an explicit algorithm allowlist (for example `["HS256"]` or `["EdDSA"]`) and never accept `none`. Choose one signing key strategy and document it in ADR-004 follow-up.
- **Keycloak** (Apache-2.0, verify) would give us a full identity server, but it is heavy for a single-VPS MVP and adds a second auth system to secure. Not recommended for MVP.
- **Authlib** (BSD-3, verify) is an alternative if we need OAuth client and server features beyond token verification.

### 2.4 Web hardening

- Caddy handles TLS with automatic certificates and sets HSTS. Add security headers in Caddy: `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Rate limits at two layers: Caddy for coarse per-IP limits; the API for per-user and per-endpoint limits (estimates are the costly route).
- CORS: allow only the web origin. Mobile apps use the Capacitor origin; allow only that.

### 2.5 Static security analysis

- **Bandit** (Apache-2.0, verify) finds Python security issues such as unsafe deserialization and weak crypto.
- **Ruff** (MIT, verify) with the `S` (bandit-style) rules is fast enough to run in pre-commit.
- **Semgrep** (LGPL-2.1 engine; rule licences vary, verify) adds custom rules, for example "no logging of `request.body`."
- **CodeQL** is free for public repositories only. If the repo stays private, CodeQL requires a paid licence. Flag this and use Semgrep and Bandit instead.
- **ESLint with security plugins** (MIT, verify) for the TypeScript client.

### 2.6 Secrets

- **gitleaks** (MIT, verify) runs as a pre-commit hook and in CI. It blocks commits with keys. Our `.gitignore` already excludes `.env` files.
- Runtime secrets come from the host environment with file permissions set to owner-only. Encrypted secrets in git use **SOPS** (MPL-2.0, verify) with **age** (BSD-3, verify).
- Run gitleaks over the full git history once before launch and rotate any key it finds. This review did not run that scan. The earlier `1234` default PIN in the client is a credential-hygiene issue to remove (ADR-003).

### 2.7 Dependencies and supply chain

- **Dependabot** (free on GitHub) opens update pull requests with security advisories. Keep it on.
- **pip-audit** (Apache-2.0, verify) and **OSV-Scanner** (Apache-2.0, verify) check Python and JavaScript dependencies against public databases. Run both in CI.
- **npm audit** is built in but uses GitHub's advisory feed; use alongside OSV-Scanner.
- **Lockfiles** are committed (`bun.lock` exists; add `uv.lock` or `requirements.lock` for Python).
- **Trivy** (Apache-2.0, verify) scans container images and Dockerfiles in CI.
- **Syft** (Apache-2.0, verify) generates an SBOM per release. **Cosign** (Apache-2.0, verify) signs images. Verify signatures before deploy.

### 2.8 Testing and evaluation

- **pytest** (MIT, verify) for unit and integration tests. **Hypothesis** (MPL-2.0, verify) for property-based tests on the estimate validator.
- **Playwright** (Apache-2.0, verify) for end-to-end tests on web and as a stand-in for mobile flows.
- **Eval harness** (in-house, 150 labelled meals, ADR-005). **promptfoo** (MIT, verify) can run the same cases across providers and produce comparison reports.

### 2.9 Observability

See `docs/observability.md`. OpenTelemetry SDK and Collector are the standard. Backend choice is open (section 4 there).

## 3. Free-tier caveats

Some tools are free only under conditions. We avoid these in MVP:

- CodeQL (public repos only).
- Snyk, Doppler, and hosted secret managers (free tiers with limits or closed source).
- Hosted observability products (usage-priced; data leaves the EU unless chosen carefully).

## 4. What "no compromise" means in practice

- Every outbound AI call is logged as a policy decision without content.
- Every release runs: lint, unit tests, OPA tests, Bandit, gitleaks, dependency audit, image scan, SBOM, eval gate. A failure blocks the release.
- Dependencies are pinned and updated through reviewed pull requests, never auto-merged for production.
- A penetration check of the `/api` routes happens before launch (PRD acceptance criterion).
- Residual risk is written down, owned, and reviewed each quarter.
